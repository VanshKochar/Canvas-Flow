1. EXECUTIVE SUMMARY & SYSTEM GOALS
================================================================================
The objective is to architect and build a modern, high-performance, enterprise-grade
collaborative digital workspace. The platform allows distributed teams to plan,
brainstorm, design user journeys, execute agile ceremonies, and map systems in real-time
on an infinite digital canvas.

Key Pillars:
- Ultra-Low Latency Multiplayer: 60 FPS local canvas rendering with sub-50ms peer-to-peer/server
  multi-cursor and stroke synchronization.
- Infinite Scalability: Canvas handles 10,000+ interactive elements smoothly through
  spatial partitioning (R-Trees / Quadtrees) and viewport culling.
- Enterprise Security & Multi-Tenancy: Granular Role-Based Access Control (RBAC),
  JWT authentication with secure token rotation, room password protections, and audit logging.
- Deep Learning & Documentation: Every design pattern, keyword, architectural tradeoff,
  and debugging session is documented step-by-step in a dedicated learning repository.

2. COMPLETE ENTERPRISE TECHNOLOGY STACK (PRODUCTION-GRADE)
================================================================================

2.1 FRONTEND ARCHITECTURE & LIBRARIES
--------------------------------------
- Core Framework: React 18 / 19 with Vite (blazing-fast HMR and optimized tree-shaking builds).
- State Management:
  * Zustand: For client-side UI state (tool selection, active colors, stroke widths, zoom levels).
    Why Zustand? Lightweight (1.5kb), zero boilerplate, avoids React re-render cascades.
  * TanStack Query (React Query): For server state caching, pagination, board metadata fetching,
    and optimistic updates.
- Styling & Theming:
  * Vanilla CSS Variables + Tailwind CSS or Modular CSS:
    Complies with user global rules: CSS variables for full light/dark/high-contrast theming,
    8px grid spacing system (8px, 16px, 24px, 32px, 48px), semantic HTML5 elements, and
    @media (prefers-reduced-motion) rules.
- UI Component Accents & Icons:
  * Lucide React: Clean, highly customizable SVG icon set.
  * Radix UI / Headless UI: Accessible, unstyled primitives for modals, dropdowns, tooltips, dialogs.

2.2 CANVAS & RENDERING ENGINE CHOICE
--------------------------------------
- Primary Rendering Engine: HTML5 Canvas 2D Context with custom matrix transformation
  and Konva.js / Fabric.js / PixiJS or Custom Hybrid Renderer:
  * Custom Matrix Transform: Supports smooth panning (drag/middle-mouse/space-bar) and pinch-to-zoom
    with mouse wheel focal point anchoring (Zoom range: 10% to 3000%).
  * Rough.js (Optional Hand-drawn style toggle): Gives hand-drawn aesthetic like Excalidraw,
    or crisp architectural vectors like Miro.
  * Perfect-Freehand: Computes pressure-sensitive Bézier curves for natural pen/stylus strokes.
  * Spatial Indexing (rbush / Quadtree): Viewport culling so off-screen elements are never drawn,
    ensuring 60fps performance even with thousands of canvas objects.

2.3 REAL-TIME MULTIPLAYER & NETWORKING LAYER
---------------------------------------------
- Real-Time Transport: WebSockets via Socket.io (with automatic fallback to HTTP Long-Polling).
- Conflict Resolution / State Sync:
  * Hybrid CRDT / Operational Transformation or Distributed Event Stream with Vector Clocks.
  * Yjs / Automerge or Granular Element-Level Last-Write-Wins (LWW) with optimistic local mutation:
    - Guarantees zero lost strokes.
    - Immediate local rendering (0ms latency), background sync to peers.
    - Cursor position broadcast with linear interpolation (Lerp) to prevent jitter.
- Presence Tracking:
  * Heartbeat pings every 5 seconds.
  * Disconnect detection within 2 seconds.
  * User presence state: { userId, name, avatar, cursor: {x, y}, activeElementId, role }.

2.4 BACKEND MICROSERVICES / MODULAR MONOLITH
---------------------------------------------
- Runtime: Node.js (v20+ / v24 LTS).
- Web Framework: Express.js with TypeScript or Modern ES6+ modules.
- Architectural Pattern: Clean Architecture (Domain Driven Design):
  * Routes Layer -> Validation Layer -> Controllers -> Services (Business Logic) -> Repositories (Data Access).
- Real-Time Server: Socket.io server integrated with HTTP server, clustered via Redis Adapter.
- Input Validation: Zod or Joi schemas on every incoming payload to eliminate injection vulnerabilities.
- Export Service:
  * Sharp / Canvas (Server-side rendering for PNG/JPEG export).
  * PDFKit / jsPDF for vector PDF documentation exports.

2.5 DATABASE & DATA PERSISTENCE STRATEGY
-----------------------------------------
- Primary Document Database: MongoDB (with Mongoose ODM) OR PostgreSQL (with Prisma/Drizzle ORM).
  * Why MongoDB for Whiteboard Elements?
    Whiteboard canvas elements are polymorphic (rectangles, ellipses, sticky notes, connectors,
    freehand paths, text frames have distinct attribute sets). Document databases represent
    heterogeneous canvas nodes with high indexing efficiency.
  * Storing Whiteboards:
    1. Board Metadata Document: Title, owner, members, access permissions, settings.
    2. Elements Collection: Each element stored as an indexed document { boardId, elementId, type,
       x, y, width, height, stroke, fill, zIndex, version, createdBy, updatedBy }.
    3. Snapshots / History: Time-travel undo/redo versions and backup points.

2.6 CACHING, PUB/SUB & SESSION STORAGE
---------------------------------------
- In-Memory Cache & Message Broker: Redis (ioredis client).
  * Purpose 1: Horizontal scaling of Socket.io using `@socket.io/redis-adapter` across multiple Node server instances.
  * Purpose 2: Caching active board state in memory for instant socket joins without querying MongoDB on every cursor packet.
  * Purpose 3: Rate limiting sliding window counter (Redis token bucket algorithm).
  * Purpose 4: Temporary token blacklist & active refresh token stores.

2.7 DEVOPS, CONTAINERIZATION & CI/CD
------------------------------------
- Docker & Docker Compose: Multi-container setup (Frontend container, Backend API container,
  MongoDB container, Redis container).
- Reverse Proxy & Gateway: Nginx (handling SSL termination, gzip/brotli compression, WebSocket upgrade headers).
- CI/CD Pipelines: GitHub Actions (Linting, TypeScript compilation, Unit tests, Cypress E2E tests,
  Docker image build & push).
- Cloud Deployment Targets:
  * Frontend: Vercel / Netlify / AWS S3 + CloudFront.
  * Backend API: AWS ECS / Render / Railway / DigitalOcean App Platform.
  * Managed Databases: MongoDB Atlas & Redis Cloud / Upstash.

2.8 MONITORING, OBSERVABILITY & ERROR TRACKING
----------------------------------------------
- Logging: Winston / Pino with structured JSON logs and correlation IDs (X-Request-ID).
- Error Monitoring: Sentry integration for real-time frontend & backend unhandled exceptions.
- Metrics & Performance: Prometheus + Grafana or Winston request latency profiler.

2.9 ENTERPRISE SECURITY, CRYPTOGRAPHY & COMPLIANCE
--------------------------------------------------
- Authentication:
  * JWT (JSON Web Tokens) with dual-token architecture:
    - Short-lived Access Token (15 mins) stored in memory / Authorization header.
    - Long-lived Refresh Token (7 days) stored in HttpOnly, Secure, SameSite=Strict cookies.
  * Password Hashing: Argon2 or bcrypt (12 salt rounds).
  * Multi-factor Authentication (MFA/2FA) ready via TOTP (Speakeasy / OTPAuth).
- Role-Based Access Control (RBAC):
  * Roles: Workspace Admin, Board Owner, Editor, Commenter, Viewer.
  * Room Token validation during WebSocket handshake.
- API Security:
  * Helmet.js for secure HTTP security headers (CSP, HSTS, X-Content-Type-Options).
  * CORS (Strict origin whitelisting).
  * Rate Limiting: express-rate-limit + Redis store to prevent brute-force and DoS.
  * Data Sanitization: DOMPurify for HTML/SVG elements to prevent Stored XSS.

4. DETAILED COMPONENT ARCHITECTURE
================================================================================

4.1 THE INFINITE CANVAS ENGINE
- Virtual Coordinate Space:
  * Screen Coordinates (pixels on physical monitor) vs Canvas Coordinates (infinite virtual world).
  * Transformation equations:
      World_X = (Screen_X - Pan_X) / Zoom_Level
      World_Y = (Screen_Y - Pan_Y) / Zoom_Level
  * Zoom Anchoring: Mouse cursor stays pinned to the exact world point during zooming.
- Interactive Tools:
  1. Selection & Transform Tool (Bounding box, multi-select, resize handles, rotation handle).
  2. Rectangle, Ellipse, Diamond, Triangle, Star.
  3. Dynamic Connectors (Straight, Orthogonal/Elbow, Curved Bézier) with magnetic shape anchors.
  4. Sticky Notes (Color palette, auto-scaling typography, markdown support).
  5. Freehand Pencil / Highlighter (Variable stroke width, smoothing algorithms).
  6. Text Block (Inline WYSIWYG editor).
  7. Stamps & Reactions (Thumbs up, Star, Heart, Warning, Question mark).
  8. Image Importer (Drag-and-drop, aspect-ratio lock, paste from clipboard).
  9. Frame / Artboard (Group and export bounded areas).
  10. Eraser (Click element eraser or stroke-slice eraser).

4.2 REAL-TIME SYNCHRONIZATION & CONFLICT RESOLUTION
- Multi-Cursor Synchronization:
  * Mouse coordinates translated to World Coordinates so different screen sizes and zoom levels
    see cursors in the exact same logical position.
  * Position throttling: 30-50 updates/second with client-side linear interpolation (lerp).
- Element State Updates:
  * Atomic delta messages: { action: "ELEMENT_UPDATE", id, changes: { x, y, width, height }, version }.
  * Optimistic updates: Local user interacts with zero lag; socket emits to server; server broadcasts to room peers.
  * Element locking: When a user selects or drags an element, a temporary lock { lockedBy: userId } is acquired
    preventing simultaneous destructive edits by other users.

4.3 TEMPLATE & FRAMEWORK LIBRARY
- Pre-built, one-click loadable canvases:
  * Agile Sprint Retrospective (What went well, What didn't, Action items).
  * Kanban Workflow Board (Backlog, In Progress, Review, Done).
  * System Architecture & Flowchart Kit (Databases, Servers, Gateways, Queues, Users).
  * UX User Journey Mapping (Stages, User goals, Touchpoints, Pain points, Opportunities).
  * Brainstorming & Mind Map Trees (Central node with radial auto-connecting branches).

4.4 ENTERPRISE RBAC & SECURITY GATEWAY
- Multi-tier Permission Hierarchy:
  * Organization Level -> Workspace Level -> Board Level.
  * Board Permissions:
    - OWNER: Full control, delete board, transfer ownership, manage member roles.
    - ADMIN: Invite members, modify board settings, export, manage content.
    - EDITOR: Create, edit, delete, transform canvas elements.
    - COMMENTER: Add sticky note comments and reactions; cannot move board structure.
    - VIEWER: Read-only viewport panning and zooming; export permissions configurable.
- Audit Logging:
  * Every destructive action (board deletion, role elevation, bulk element clear) logged with
    timestamp, IP address, user agent, and user ID.

4.5 PRESENTATION, INTERACTIVE TIMER & VOTING ENGINE
- Presentation Mode ("Follow Me"):
  * Presenter activates "Broadcast Viewport".
  * Followers' viewports automatically pan and zoom to match presenter's camera in real time.
- Collaborative Timer:
  * Synchronized countdown timer stored in Redis.
  * Start, pause, reset broadcast to all connected team members with audio chime on finish.
- Voting Sessions:
  * Board admin starts a 3-minute dot-voting session.
  * Team members get N votes (stamps) to place on ideas or sticky notes.
  * Real-time tally and leaderboard revealed at the end of the session.

5. DATA MODELS & SCHEMAS (MONGODB / POSTGRESQL EQUIVALENT)
================================================================================

1. USER SCHEMA:
   - _id: ObjectId
   - email: String (unique, indexed)
   - passwordHash: String (Argon2 / bcrypt)
   - fullName: String
   - avatarUrl: String
   - role: Enum ('superadmin', 'member', 'guest')
   - preferences: { theme: 'light'|'dark'|'system', gridVisible: Boolean, snapToGrid: Boolean }
   - createdAt, updatedAt: Timestamps

2. BOARD SCHEMA:
   - _id: ObjectId
   - title: String (indexed)
   - description: String
   - ownerId: ObjectId (ref: User)
   - workspaceId: ObjectId
   - isPublic: Boolean (default false)
   - passwordHash: String (optional room password)
   - members: [{ userId: ObjectId, role: 'admin'|'editor'|'viewer'|'commenter', addedAt: Date }]
   - settings: { backgroundColor: String, gridType: 'dots'|'lines'|'none', snapDistance: Number }
   - thumbnailDataUrl: String (auto-generated preview)
   - version: Number (incremented on each snapshot)
   - isArchived: Boolean
   - createdAt, updatedAt: Timestamps

3. ELEMENT SCHEMA (Stored in Elements collection or nested snapshot):
   - _id: String / ObjectId (Unique element identifier)
   - boardId: ObjectId (indexed)
   - type: Enum ('rectangle', 'ellipse', 'diamond', 'sticky', 'text', 'pen', 'connector', 'stamp', 'image')
   - x: Number
   - y: Number
   - width: Number
   - height: Number
   - rotation: Number (degrees)
   - zIndex: Number (layer ordering)
   - strokeColor: String
   - strokeWidth: Number
   - strokeStyle: Enum ('solid', 'dashed', 'dotted')
   - fillColor: String
   - opacity: Number
   - text: String (for text, sticky notes)
   - fontSize: Number
   - fontFamily: String
   - textAlign: Enum ('left', 'center', 'right')
   - points: Array of [x, y] (for freehand pen strokes)
   - connectorStart: { elementId: String, anchor: 'top'|'bottom'|'left'|'right' }
   - connectorEnd: { elementId: String, anchor: 'top'|'bottom'|'left'|'right' }
   - lockedBy: ObjectId (transient lock holder)
   - version: Number
   - createdBy: ObjectId
   - updatedBy: ObjectId
   - createdAt, updatedAt: Timestamps

6. WEBSOCKET REAL-TIME PROTOCOL SPECIFICATION
================================================================================

Client -> Server Events:
- `board:join`        Payload: { boardId, token, password? }
- `board:leave`       Payload: { boardId }
- `cursor:move`       Payload: { boardId, x, y } (throttled to 30ms)
- `element:create`    Payload: { boardId, element }
- `element:update`    Payload: { boardId, elementId, updates, version }
- `element:delete`    Payload: { boardId, elementIds: [] }
- `element:lock`      Payload: { boardId, elementId }
- `element:unlock`    Payload: { boardId, elementId }
- `timer:start`       Payload: { boardId, durationSeconds }
- `timer:pause`       Payload: { boardId }
- `present:start`     Payload: { boardId }
- `present:viewport`  Payload: { boardId, panX, panY, zoom }
- `present:stop`      Payload: { boardId }

Server -> Client Events:
- `board:init`        Payload: { elements, users, timer, settings }
- `user:joined`       Payload: { user: { id, name, avatar, role, color } }
- `user:left`         Payload: { userId }
- `cursor:update`     Payload: { userId, x, y }
- `element:created`   Payload: { element }
- `element:updated`   Payload: { elementId, updates, updatedBy, version }
- `element:deleted`   Payload: { elementIds: [] }
- `element:locked`    Payload: { elementId, lockedBy }
- `element:unlocked`  Payload: { elementId }
- `timer:tick`        Payload: { remainingSeconds, isRunning }
- `present:sync`      Payload: { presenterId, panX, panY, zoom }
- `error:message`     Payload: { code, message }
